# AAGAHI API contract — risk assessment

Status: **no backend implements this yet.** `RiskRemoteDataSourceImpl`
(`aagahi-app/lib/features/risk/data/datasources/risk_remote_data_source_impl.dart`)
is written against this document; `Dio`'s default `baseUrl` is a reserved,
never-resolving address (RFC 2606 — `api.aagahi.invalid`), so every call
fails with `NetworkException` until a real API exists at
`--dart-define=API_BASE_URL=...`. That failure is what makes
`RiskRepositoryImpl`'s offline-first fallback to the Drift cache the thing
actually running today, not a demo-only figure of speech.

## `GET /v1/parcels/{parcelId}/risk-assessment`

Two response shapes, both HTTP 200. **Not-scorable is a successful response
about a valid parcel — it is not a 4xx.** A 422 (or any other client-error
code) can be generated by a proxy, a WAF, or a future API gateway for
reasons that have nothing to do with scorability; a client that treats 4xx
as "not enough data" would misrender an unrelated failure as this project's
single most safety-critical UI state. See CLAUDE.md §1.

### Scored

```json
{
  "parcelId": "p1",
  "assessedOn": "2026-08-23T00:00:00.000Z",
  "probability": 0.71,
  "riskBand": "warning",
  "horizonDays": 14,
  "drivers": [
    {
      "featureName": "vpd_anomaly_z",
      "contribution": 0.19,
      "direction": "increasesRisk",
      "narrativeKey": "driver.evaporativeDemand",
      "relativeWeight": 1.0
    }
  ],
  "trace": [
    { "date": "2026-08-10T00:00:00.000Z", "percentile": 82.0 }
  ],
  "modelVersion": "v2026.08",
  "completenessRatio": 1.0,
  "confidenceLower": 0.58,
  "confidenceUpper": 0.81,
  "usedDegradedInputs": false,
  "isRainFed": true,
  "advisoryTitleKey": "advisory.cutWeedsAndMulch",
  "advisoryBodyKey": "advisory.cutWeedsAndMulch.body",
  "voiceBriefingUri": null
}
```

Field names and types are exactly `RiskAssessmentModel.toJson()` /
`.fromJson()` (`aagahi-app/lib/features/risk/data/models/risk_assessment_model.dart`)
— that model is the single source of truth for this shape; this document
describes it, it does not define a second copy of it.

### Not scorable

```json
{ "scorable": false, "reason_key": "notScorable.insufficientCoverage" }
```

`reason_key` is a localisation key naming the missing input in plain
language (FR-PRED-009), resolved client-side the same way every other
narrative/label key in this app is.

Any body containing `"scorable": false` is treated as this shape,
regardless of other fields present. Any other 200 body is parsed as the
scored shape above.

## `GET /v1/briefings/{assessmentId}`

Returns the pre-rendered audio file bytes for a WARNING+ assessment
(`Content-Type` appropriate to the audio format) on 200. Not yet exercised
by any real backend — see status note above.

## Errors

| HTTP status | Client exception | Failure surfaced to the user |
|---|---|---|
| 401 / 403 | `AuthException` | `AuthFailure` |
| any other non-2xx | `ServerException(statusCode)` | `ServerFailure` (falls back to cache if one exists) |
| no response (DNS/connection/timeout) | `NetworkException` | `NetworkFailure` (falls back to cache if one exists) |
| 200 with a body that doesn't parse | `FormatException` | `ServerFailure` (falls back to cache if one exists) |

`connectTimeout` is 5 seconds (`buildDio` in
`aagahi-app/lib/core/network/dio_client.dart`) — a demo audience should see
the offline fallback within seconds when no backend is configured, not wait
out a default 30+ second timeout to find out there is none.

## Known gaps

- **No authentication.** FR-AUTH's OTP/token flow doesn't exist yet; no
  request here carries an `Authorization` header. The 401/403 mapping above
  is wired for when it does, not exercised by anything yet.
- **No certificate pinning.** NFR-SEC-001/CI-02 require it; there is no real
  server to pin a certificate to yet. Documented here as a gap, not
  silently skipped — do not treat `buildDio` as done with respect to those
  requirements.
- **RFC 9457 Problem Details** (SRS §5.3.3) is not implemented for error
  bodies — errors are distinguished by HTTP status code only. Revisit once
  a real API exists to agree the error body shape with.
